# 工程量审减分析助手

Windows 10/11 离线桌面工具，用于对比送审工程量清单、审计初审清单和审计终审清单，并输出对比工作簿及独立的审减分析报告。

本项目已经开源，源代码采用 [MIT License](LICENSE)。程序离线处理文件，不上传送审、初审或终审清单。

## 快速开始

开发环境需要 Windows 10/11 和 .NET SDK 10.0.400。

```powershell
git clone https://github.com/yang123-pot/EngineeringQuantityAuditComparer.git
cd EngineeringQuantityAuditComparer
dotnet build EngineeringQuantityAuditComparer.slnx --configuration Release
dotnet run --project src/EngineeringQuantityAuditComparer.App/EngineeringQuantityAuditComparer.App.csproj
```

程序运行所需的报表模板位于 `assets/ReportTemplate.xlsx`，克隆仓库后无需再从其他目录复制模板。

## 安装与更新

在 [Releases](https://github.com/yang123-pot/EngineeringQuantityAuditComparer/releases) 下载最新的 `工程量审减分析助手-版本号-安装程序.exe`，双击后按提示安装。安装程序会创建桌面和开始菜单快捷方式；以后下载的新版本可从任意文件夹运行，安装到同一位置。

如果电脑上装有旧 ClickOnce 版，安装程序会自动移除对应旧版后再安装新版。未能确认旧版移除时，新版会停止安装并给出提示。免安装版仍可直接解压运行。

## 使用流程

送审文件是必选文件；初审和终审至少选择一份，因此支持以下三种组合：

- 送审 + 初审
- 送审 + 终审
- 送审 + 初审 + 终审

三个文件分别放入送审、初审、终审卡片，也可以拖入对应卡片。自动分析后始终进入“确认单位工程匹配”页面。单位工程表显示全部送审、初审、终审单位工程；送审顺序固定，可选中一行后分别使用“初审上移/下移”或“终审上移/下移”调整实际配对。系统对明确缺项自动备注“初审未给”“终审未给”“初审新增”或“终审新增”，这些备注不要求人工确认；重名、名称近似、多候选和人工调整后的单位工程配对必须勾选人工确认。单位工程确认完成后即可进入预览，在预览页补充人工说明并导出两份 `.xlsx` 文件。

软件自动识别原“单项工程投标报价汇总表／分部分项工程和单价措施项目清单与计价表”和新版“表E.1.1-2／表E.2.1”格式。清单项目不再显示异常候选或要求人工确认。任意两个阶段的清单项目只有在“项目名称＋项目特征描述＋计量单位”归一化后全部一致时才允许自动匹配；项目编码相同也不能绕过这三项限制。编号或描述为空的有效清单项仍会导入、对比；编号缺失且另外三项唯一一致时标记为“名称特征单位匹配（编码缺失）”。三项任一不一致或存在多个无法唯一确定的候选时，送审侧保留为审核未计，审核侧项目直接作为新增项输出。旧的人工清单关联配置不再参与匹配。

## 输出结构与计算口径

- 导出工作簿前三页固定为“绝对差额 Top 20看板”“同类清单审增审减汇总看板”“汇总表”，其后为各单位工程明细页。所有用户可见差额只采用“送审－初审”或“送审－终审”，三阶段也不输出“终审－初审”。审减率以送审金额的绝对值为分母；送审和审核均为 0 时为 0，送审为 0 且审核非 0 时按差异符号记为 `-100%`。
- 同目录另生成 `<对比文件名>-审减分析报告.xlsx`。单审核阶段有“审减概况、扣减项明细”两页；初审和终审都有时按阶段生成四页。概况使用含税造价；明细按项目名称＋计量单位列行，核减工程量、核增工程量、审减金额及审增金额各设“合计＋逐楼栋”列，合计由楼栋列求和。金额取自分部分项清单的不含税合价差；楼栋优先按清单分部标题识别，再按单位工程名称识别，无法可靠归属的单列待核查，不强行记入某栋。不同计量单位的工程量不跨项合计。特征描述与单位相同但名称不同的项目保留为独立行，并在“名称核查”列提示疑似同类。
- 明细页工作表名称来自清单页内的“工程名称”，而不是 Excel 页签名。每个差异组固定包含“工程量差、单价差、合价差、合价差异率”四列；差额按对应审核口径计算。单边缺失的工程量、综合单价和合价写入真正的数值 `0`，审计新增项目的序号留空。某项目所有有效审核口径的合价差异率实际数值均为 `0` 时，不写程序自动批注；人工填写的批注仍保留。
- 有源标题结构时，输出保留源标题与对应的 `分部小计` 以及源小计金额；按匹配项目锚点插入名称不同的审计阶段标题，并在选定阶段缺少标题时写入数值 `0`。`单价措施合计` 不纳入“整个工程”根标题。根标题、各级标题和项目行分别使用大纲级别 0、1、2（更深层级继续递增），导出后默认全部展开。无标题结构的旧表继续使用项目行和底部小计的兼容格式；即使存在没有对应小标题的孤立 `分部小计`，也会忽略该结构行并直接按项目平铺对比。只要表内存在真实小标题，`分部小计` 仍必须与小标题正确配对。
- 汇总表中的单位工程名称可跳转到对应明细页顶部，“绝对差额 Top 20看板”的清单序号可跳转到具体项目行。Top 20 和同类清单汇总只读取项目行，不把“整个工程”或标题行纳入统计。

“绝对差额 Top 20看板”和“同类清单审增审减汇总看板”在三阶段模式均只展示初审阶段（送审－初审）和终审结算（送审－终审）两个口径；双阶段模式只展示所选审核节点对应的一个口径。

同类清单看板优先使用“项目特征描述+计量单位”作为键，特征为空时使用“项目名称+计量单位”；编码不参与合并，不同单位分开统计，单个单位工程的清单也保留。每个口径按“审减金额、审增金额”分列，并在备注中列出“单位工程／系统”；不包含涉及单位工程数、工程量、节点合价或净变化。无结果时显示“无审增审减清单”。

正负差异使用 Excel 原生条件格式，正数表示审减并显示红色，负数表示审增并显示绿色，零值保持默认颜色；修改表内数据后公式和颜色可随结果变化。程序离线运行，不修改、不覆盖输入文件，也不会覆盖已存在的导出文件。

## 开发与验证

解决方案使用 .NET SDK 10.0.400，并锁定 ExcelDataReader 3.9.0、ClosedXML 0.105.1、CommunityToolkit.Mvvm 8.4.2。构建独立安装程序还需要 [Inno Setup 7](https://jrsoftware.org/isdl.php) 的 `ISCC.exe`。

```powershell
dotnet test EngineeringQuantityAuditComparer.slnx --configuration Release
./build/Publish.ps1
```

开源包结构可单独验证：

```powershell
pwsh ./tests/OpenSourcePackage.Tests.ps1
```
